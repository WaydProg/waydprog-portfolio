# WaydProg — портфолио

Личный сайт-портфолио: сайты и Telegram-боты. Vite + React + TypeScript (strict), чистый CSS
на дизайн-токенах, хостинг — Firebase Hosting.

## Быстрый старт

Нужен Node.js 22.18 или новее (скрипты в `scripts/` запускаются напрямую из TypeScript).

```sh
npm install
npm run dev        # http://localhost:5173
```

| Команда               | Что делает                                                 |
| --------------------- | ---------------------------------------------------------- |
| `npm run dev`         | Локальный сервер разработки                                |
| `npm run add-project` | Интерактивно добавляет новую работу (см. ниже)             |
| `npm run validate`    | Проверяет `projects.json` по схеме и наличие всех картинок |
| `npm run build`       | Проверка данных → типы → сборка → пререндер HTML в `dist/` |
| `npm run preview`     | Открывает собранный `dist/` локально                       |
| `npm run lint`        | ESLint без предупреждений                                  |
| `npm run format`      | Prettier                                                   |
| `npm run check`       | Линт + проверка форматирования + сборка                    |
| `npm run deploy`      | Сборка и публикация на Firebase Hosting                    |

## Как добавить новую работу

Компоненты трогать не нужно: все проекты лежат в `src/data/projects.json`, картинки — в
`public/projects/<slug>/`.

1. Подготовьте скриншоты (PNG, JPG или WebP). Первый станет обложкой в превью, поэтому лучше
   брать первый экран сайта 1440×900. Скриншоты с телефона тоже подходят — в карточке они
   встанут в отдельный ряд.
2. Запустите:

   ```sh
   npm run add-project
   ```

   CLI спросит название, адрес (slug), тип (САЙТ/БОТ), метку (РЕАЛЬНЫЙ / ДЕМО-ПРОЕКТ), формат,
   описания, что сделано, стек, статус, ссылки и пути к скриншотам. Файл можно просто перетащить
   в окно терминала. Картинки автоматически ужимаются в WebP нескольких ширин
   (640/960/1280 px, для вертикальных — 360/720 px).

3. Проверьте результат: `npm run dev`.
4. Опубликуйте: `npm run deploy`.

Порядок в списке — порядок в `projects.json`; первый проект активен по умолчанию. Чтобы
поменять порядок, поправить текст или удалить работу, отредактируйте файл вручную (для
удаления также удалите папку `public/projects/<slug>/`). Ошибки в данных `npm run build`
покажет с точным путём к полю.

### Поля проекта

| Поле          | Пример                               | Где видно                                |
| ------------- | ------------------------------------ | ---------------------------------------- |
| `slug`        | `gigkod`                             | папка с картинками                       |
| `title`       | `Gigkod`                             | список, превью, карточка                 |
| `type`        | `site` или `bot`                     | метка САЙТ / БОТ                         |
| `kind`        | `real` или `demo`                    | РЕАЛЬНЫЙ ПРОЕКТ / ДЕМО-ПРОЕКТ            |
| `format`      | `Лендинг`                            | подпись под превью                       |
| `summary`     | `Биржа IT-специалистов`              | строка списка                            |
| `description` | абзац текста                         | карточка проекта                         |
| `tasks`       | `["…", "…"]`                         | «Что сделано»                            |
| `stack`       | `["React", "FastAPI"]`               | подпись превью (первые три) и карточка   |
| `stats`       | `[{"value": "232", "label": "…"}]`   | цифры в карточке, можно оставить пустым  |
| `links`       | `[{"label": "…", "url": "https…"}]`  | ссылки в карточке, можно оставить пустым |
| `status`      | `Концепт`                            | карточка                                 |
| `thumb`       | `{"label": "GIGKOD", "tone": "sky"}` | миниатюра в списке                       |
| `images`      | заполняет CLI                        | превью и галерея                         |

Тона миниатюр: `lime`, `lavender`, `sage`, `sky`, `sand`, `ink`.

## Ссылки на профили и тексты

- `src/data/links.ts` — Kwork, FunPay, Playerok, Telegram-канал. Пункт с `url: null` на сайте
  не показывается; впишите адрес, и он появится в блоке контактов.
- `src/data/content.ts` — hero, «Обо мне», услуги, стек, процесс, FAQ, контакты.
- `src/data/site.ts` — юзернейм и подписи в шапке.

## Деплой на Firebase Hosting

Конфигурация уже готова: `firebase.json` (папка `dist`, SPA-rewrites, долгий кеш для
`/assets`, заголовки безопасности) и `.firebaserc` с проектом `waydprog-portfolio`.

Один раз:

```sh
npm install -g firebase-tools   # если ещё не установлен
firebase login                  # откроет браузер для входа в Google
```

Создайте проект `waydprog-portfolio` в [консоли Firebase](https://console.firebase.google.com)
и включите в нём Hosting, либо из терминала:

```sh
firebase projects:create waydprog-portfolio
```

Если ID проекта получится другим (например, занят), замените его в `.firebaserc`, а адрес
`https://waydprog-portfolio.web.app` — в `index.html`, `public/robots.txt` и
`public/sitemap.xml`.

Публикация:

```sh
npm run deploy
```

Проверить конфигурацию хостинга без публикации можно в эмуляторе:
`firebase emulators:start --only hosting --project demo-waydprog`.

## Структура

```
scripts/            add-project, проверка данных, пререндер, оптимизация картинок
src/
  components/
    layout/         шапка, футер, кнопка «Наверх»
    sections/       hero, обо мне, услуги, стек, процесс, FAQ, контакты
    works/          список работ, превью, карточка проекта
    ui/             общие мелкие компоненты
  data/             projects.json, тексты, ссылки
  hooks/            React-хуки
  lib/              схема проектов, пути к медиа, форматирование
  styles/           токены, шрифты, базовые стили
public/             иконки, og-image, скриншоты проектов
```

## Git

- `main` — стабильная ветка, из неё деплой; релизы помечаются тегами (`v1.0.0`).
- `develop` — интеграционная ветка.
- `feature/*` — новые функции, вливаются в `develop` через `git merge --no-ff`.
- Сообщения коммитов — Conventional Commits на английском (`feat:`, `fix:`, `docs:` …).

Добавить работу можно прямо в `develop`:
`git commit -m "feat: add <slug> project"`, затем влить `develop` в `main` и выполнить
`npm run deploy`.
